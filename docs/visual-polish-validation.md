# Visual polish guidance: bounded behavior review

The new `engine-visual-polish` skill was exercised with the same Unreal combat-racer request and raw project artifacts as an independent baseline. The evaluator with the skill did not receive the baseline answer or the research report. Both inspected the same frozen runtime stills, approved references, material construction, rendering config and vehicle effect signals. Neither executed the engine or changed the game.

The baseline was already competent: it diagnosed the Unlit material contract, proposed a bounded stretch, reused real contact signals and suggested a moving AA comparison. This is not evidence of a failing baseline or a measured general improvement.

The with-skill answer additionally made the per-owner component budget explicit, separated fixed-step behavior from rendering performance, distinguished tire/contact/boost/damage shapes and declined an unconditional Niagara migration. It retained the full reference bar and did not claim that source inspection established visible timing. These are observed decisions in one exercise, not a score or proof of AAA quality.

Structural validation covers frontmatter, routing links, evidence labels, size budgets, README registration and CI configuration. Description inspection separates this skill from engine selection, routine asset import and isolated rendering bugs. Automatic selection and cross-genre benefit remain unverified; future real uses should add paired evidence rather than treating this exercise as universal validation.

No Niagara integration, target-hardware performance, continuous-motion capture or runtime visual improvement is established by this documentation change. The workflow calls for those artifacts when applied to a game.
