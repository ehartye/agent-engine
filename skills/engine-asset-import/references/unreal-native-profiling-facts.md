# Unreal profiling: exactness proofs, engine-source facts and tooling traps

Companion to [native profiling](unreal-native-profiling.md) (DEAD REDLINE, Unreal 5.8.2 CL56702186, Windows, 2026-10-20). The method is in [profiling method](../../engine-phaser/references/profiling-method.md). Read an engine fact from the installed source before predicting a cost from it.

## Exactness ladder for performance fixes

- [tested] Exact fixes were built as runtime switches (`-DRProto=pilot,hazfar,effects,memo` or `all`) that are off by default. With `-DRVerifyProto` each switch computes the original result beside the new one and counts mismatches into the race receipt. One Spill race checked 14,169,728 pilot cells, 2,217,072 puddle far-rejects (zero violations), 307,135 effect transforms and 227,819 memo hits, all with zero mismatches; one 60 s verify race on each of routes 0, 1, 2, 3, 5 and 6 reported zero mismatches and zero violations.
- [tested] Whole-race trajectory file equality is not a usable proof here. `rivalrace-trajectory.csv` (one row per racer per second) differed between repeats of the same unchanged headless build: the first difference was an armor value of 158.4 against 160.0 at about 19 s of race clock. `-Deterministic -FPS=60` fixes the step and seed; it does not make the race reproducible. Check that two unchanged runs agree before using any comparison as proof, and prefer the side-by-side counters.
- [tested] Non-exact ideas stay prototypes until the owner approves: a scenery animation skip beyond 200 m of the camera (far items hold their last pose, `-DRProto=scenerylod`) measured 7.23 ms against 7.19 without it in the combined run, no measurable gain. A cached puddle penalty field and a lower AI planning rate change paths and outcomes and were held back for review.
- [tested] Measure every fix alone and combined. The merged effect transform gave no gain headless; the pilot hoist gave 3.2 ms; together the exact set took Spill from 13.06 to 7.18 ms rendered.

## Engine facts read from the installed 5.8.2 source

- [documented] `USceneComponent::SetWorldScale3D` converts to a relative scale and calls `SetRelativeScale3D`, which (when the value changed) calls `UpdateComponentToWorld`. That recomputes the component transform, propagates the update to attached children (`PropagateTransformUpdate`) and reaches `UPrimitiveComponent::OnUpdateTransform`, which updates the physics body scale. An unchanged scale is already skipped, so a per-frame scale on many pooled components pays this every time the value moves.
- [documented] `USceneComponent::OnVisibilityChanged` calls `MarkRenderStateDirty`, and so does `UStaticMeshComponent::SetStaticMesh`. Toggling visibility or meshes per frame marks render state dirty; count toggles (the game's `EffectVisibilityToggles` counter) instead of assuming they are free.
- [documented] `UPrimitiveComponent::SetCustomPrimitiveData*` writes only when the values changed and then calls `Scene->UpdateCustomPrimitiveData`, a cheaper path than a render-state recreate. Changing the default custom data marks render state dirty.
- [documented] `UActorComponent::ExecuteRegisterEvents` creates render state only when `FApp::CanEverRender()`. A `-nullrhi` run discards render data and never sends transforms to a scene, so it cannot measure render-side cost, and the Blender port found that merging imported meshes through render data produced nothing headless. Pair every headless attribution with a rendered check.
- [documented] `UInstancedStaticMeshComponent` has `InstanceStartCullDistance`, `InstanceEndCullDistance` and `bUseGpuLodSelection` (`r.InstancedStaticMeshes.GpuLod`). Component-level draw distance tests the component's bounds, so a culled chunk must be smaller than the cull distance. Details and the kit design are in the Dead Redline wiki note on scenery kits.
- [general] `ParallelFor` over game-thread work is only exact if each index reads an immutable snapshot and writes its own output slot, with no shared accumulator or random stream. This game does not use it; apply the exact-proof counters before shipping one.

## Tooling traps

- [tested] Unreal Insights tracing works on a Development build: `-trace=cpu,frame,counters,bookmark,region,log` (add `gpu` for rendered) with `-tracefile=` and `-statnamedevents`. A Test-configuration build cannot be taken on this engine distribution; UBT reports "Targets cannot be built in the Test configuration with this engine distribution". Trace Development and measure the overhead against untraced runs (5 to 8%).
- [tested] Bracket the measured part of a race with a trace region (`DRRace`, begun after the sampler warm-up) so the export covers only that part. Export headlessly with `UnrealInsights.exe -OpenTraceFile=... -NoUI -AutoQuit -ExecOnAnalysisCompleteCmd="@=export.rsp"` and `TimingInsights.ExportTimerStatistics ... -region=DRRace`. Divide a timer's inclusive time by the call count of `FEngineLoop::Tick` for ms per frame. Delete the trace after export unless asked to keep it: a rendered Spill trace is about 2 GB.
- [tested] Use trace counters for work the timers cannot express (items touched: transform calls, live effects, pilot hazard cells, visibility toggles, suspension traces) and name scopes `DR/<Area>/<What>` so one filter selects them.
- [tested] Contamination seen in this investigation: the first headless batch was thrown away, the owner reclaimed the GPU during a rendered window, and building a package while a benchmark ran disturbed both. Ask for a GPU window, run one rendered race at a time, never build during a matrix, and log why a run was discarded.
- [tested] PowerShell: `-Routes 0 6` binds 6 to the next positional parameter; pass `-Routes 0,6`. Git Bash cannot run `.ps1` here (execution policy); use PowerShell. The edit transport used here lost literal backslash-n in here-string/heredoc edits; writing edit scripts to a file avoided that problem. Windows long paths need a `\\?\` prefix to delete.
- [tested] Check free disk before each run (about 12 GB guard), because traces are large (a rendered Spill trace is about 2 GB), and write one log line per race so an unattended night can be audited afterwards.
